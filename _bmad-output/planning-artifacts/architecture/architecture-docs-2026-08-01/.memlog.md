- (override) Headless Fast path. The skill defaults to Coaching and says hold the line; the headless reference overrides it. No greeting, no menus, no purpose-and-audience probe. Reviewer Gate lenses recorded as not run (session forbids spawning subagents); spine is complete-but-unreviewed.
- (constraint) Brownfield reality ratified by reading the repo, not assumed: Gemfile has exactly two gems (jekyll ~> 4.3.4, just-the-docs 0.10.0 exact); _config.yml is 8 useful lines with no plugins/exclude/permalink/defaults key; ci.yml runs only bundle exec jekyll build; pages.yml pins ruby 3.3 inline with the comment 'Not needed with a .ruby-version file' and carries a 3-attempt deploy retry.
- (decision) Paradigm: pipes-and-filters. rake check is a linear pipeline of four independent stages over one artifact (_site/), each a filter that reads the previous stage's output and exits nonzero. Prevents the drift where each new check invents its own invocation, its own output format, and its own idea of what failure means.
- (decision) script/check.rb is a ~60-line runner; every assertion is its own file under script/checks/ auto-loaded by Dir.glob and self-registering via Check.register(id:, desc:, covers:). Rejected a monolithic check.rb: 20 assertions arriving from 11 epics would collide on the same file at the same place, and a story that hits a merge conflict skips DoD clause (b).
- (decision) rake check aborts after stage 1 (jekyll build) but RUNS stages 2-4 to completion and aggregates failures before exiting nonzero. Rejected plain Rake task-dependency fail-fast: a docs author fixing 12 findings wants all 12 in one run, not 12 sequential CI round-trips. Build is the exception because nothing downstream can run without _site/.
- (decision) Every check declares covers: [story or FR ids]. rake check:coverage lists backlog items with no covering assertion and rake check:manifest regenerates _data/checks.yml, which /docs-health renders. This makes DoD clause (b) auditable rather than self-reported, and wires Epic 1 to Epic 9 with no extra machinery.
- (decision) rake check:new[id,slug] scaffolds a checks/ file from a template. Rationale: clause (b) is non-negotiable but only if it is cheap; if adding an assertion costs more than the change itself, every story skips it and the harness becomes decorative.
- (decision) Every _data/*.yml is a mapping with exactly two top-level keys, meta (owner, verified_on, source) and items (list of mappings). One generic assertion validates that envelope for all data files; per-file required keys are a plain Ruby array in that file's check. No schema library, no JSON Schema, no dry-schema gem.
- (decision) TODO(owner: NAME): text markers live in _data values, never fail the build, and are inventoried on /docs-health. A malformed marker (no owner, no description) DOES fail. Rationale: a visibly missing figure is honest and shippable; an invented one is the failure mode the whole workstream exists to prevent, and a blocking marker would just get deleted.
- (decision) Non-HTML output mechanism stated precisely: Jekyll converts BY EXTENSION, so the source file is named with the target extension (llms.txt, fixtures/v1/x.json) and carries front matter with layout: null plus permalink:. A .md source would be kramdown-converted to HTML regardless of layout. jekyll-sitemap owns sitemap.xml.
- (decision) Spectral (OpenAPI) is NOT inside rake check. It is a separate rake lint:openapi task and its own ci.yml step. Rationale: rake check must stay runnable on a contributor machine with Ruby plus one Go binary; a node toolchain is a tax every contributor pays for a file most stories never touch. check.rb asserts that if openapi.yaml exists then ci.yml contains the spectral step, so the wiring cannot be forgotten.
- (decision) External link checking never runs on the PR path. html-proofer runs --disable-external in rake check; lychee sweeps externals nightly and files or updates one GitHub issue. Rationale: a third-party outage reddening an unrelated PR trains contributors to ignore CI, which costs more than a stale outbound link.
- (decision) Plugin budget is three: jekyll-sitemap, jekyll-redirect-from, jekyll-seo-tag. seo-tag adopted despite duplicate-canonical risk against just-the-docs own head, paired with an assertion that every page emits exactly one link rel=canonical. A fourth plugin requires amending this spine.
- (decision) Add .ruby-version pinned to 3.3 and delete the inline ruby-version key from ci.yml and pages.yml (setup-ruby reads the file). Do NOT add a ruby directive to the Gemfile: it would break bundle install on the developer local 3.1.3 immediately. rake check:env WARNS on a version mismatch rather than failing, so local work is never blocked by the upgrade.
- (constraint) Vale is a required Go binary; check:prose fails with an actionable install line if absent. Accepted because it is one static binary with no toolchain, which is a different cost class from requiring node.
- (decision) AD-14: navigation restructure needs zero redirects because just-the-docs resolves parent: by page title not directory; only real file moves and deletions require jekyll-redirect-from, asserted against _data/baseline.yml.
- (assumption) Three plugin versions (sitemap, redirect-from, seo-tag) and the current stable versions of Vale, Spectral and lychee are deliberately left as latest-at-adoption in the Stack table. No web verification was possible in this headless run, and naming a version never installed would be exactly the unsourced claim this project exists to eliminate. The adopting story must pin what it installed.
- (question) jekyll-seo-tag duplicate-canonical behaviour against just-the-docs 0.10.0 head is asserted-not-verified; the AD-11 pairing assertion converts the risk into a caught failure but the first run may need a defaults: adjustment.
