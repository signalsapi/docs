## Critical Implementation Rules

### Framework-Specific Rules (Jekyll + just-the-docs)

- **Deployment is NOT the GitHub Pages gem whitelist.** Because `pages.yml` builds with a plain `bundle exec jekyll build` on a normal Ubuntu runner, **arbitrary Jekyll plugins and custom generators in `_plugins/` are legal**. Do not reject a plugin on "GitHub Pages does not allow it" grounds — that constraint does not apply here.
- **Adding a plugin requires two edits, not one:** the gem in the `Gemfile` AND a `plugins:` array in `_config.yml`. `_config.yml` has no `plugins:` key today, so the first plugin story must create it.
- just-the-docs navigation is driven by front matter only: `title`, `nav_order`, `parent`, `has_children`, `nav_exclude`. There is no nav data file.
- `nav_order` values are floats used as insertion shims (`1.5`, `3.5`, `3.6`, `3.7`, `2.5`, `11.1`–`11.3`) — evidence of pure accretion. **`is-it-working.md` and `privacy-policy.md` both declare `nav_order: 6`; `nav_order: 5` is unused.** Resolve collisions by renumbering, never by adding another decimal.
- Every root page currently declares `layout: home`, including leaf content pages. `layout: default` is the correct just-the-docs layout for a content page; changing a layout changes the rendered nav and the search index.
- `features/index.md` is a 10-word landing page with `nav_order: 3` and no `has_children: true`, so `features/*` pages are siblings of root pages rather than nested children.
- **Liquid-only rendering.** Data lives in `_data/*.yml` and is read as `site.data.<name>`. There is no build-time scripting language available in a page. Anything a page needs must be in `_data/`, in front matter, or in a `_plugins/` generator.
- To emit a non-HTML file (JSON, txt, XML) from a Jekyll page, give it front matter with `layout: null` and a `permalink:`. This is the mechanism for `llms.txt`, fixture JSON and `plane-status.json`.

### Language-Specific Rules (Ruby / Liquid / YAML)

- Any Ruby helper script is **plain stdlib Ruby**. Do not add a Ruby dependency to satisfy a script; `script/check.rb` must run under `ruby script/check.rb` with no gems beyond what the Gemfile already installs (`yaml`, `json`, `find` are stdlib).
- YAML front matter is currently parsed leniently. Turning on `strict_front_matter: true` in `_config.yml` converts malformed front matter from a warning into a build failure — that is intended, but it means a single bad `.md` breaks the whole build.
- Front-matter strings containing `:` or starting with `#`, `&`, `*`, `{` must be quoted or the build will fail once strict mode is on.
- `_data/*.yml` keys are surfaced verbatim into Liquid. Use snake_case keys; never rename a `_data` key without updating every `site.data` reference in the same commit.

### Testing Rules

- **There is no unit-test framework in this repository and none is wanted.** Do not add RSpec, Minitest, jest, pytest or any code-coverage target. Do not write unit tests.
- The single quality gate is `bundle exec rake check` = `jekyll build` → `html-proofer` → `vale` → `ruby script/check.rb`, exiting nonzero on the first failure. `ci.yml` runs exactly that one command.
- `bundle exec jekyll build` alone is **not** an acceptable signal. It currently exits 0 in 0.52 s with every known defect present, including dead internal links, a duplicated `nav_order`, malformed canonical URLs and publicly served shell scripts.
- html-proofer is the primary gate. Run it `--disable-external` in the PR path; external link checking belongs in a nightly job (lychee), never in the build loop.
- Vale is a Go binary configured by `.vale.ini` + `styles/SignalsAPI/`. Error-level rules must exit 1.
- Accessibility is checked by html-proofer's alt-text assertion plus a contrast constant asserted in `script/check.rb` against `_sass/color_schemes/signalsapi.scss`. Headless-browser a11y runners (pa11y-ci, axe) are deliberately excluded from the loop.
- **Definition of Done for every change:** (a) `bundle exec rake check` is green, AND (b) the change adds at least one new assertion to `script/check.rb` or a new rule to `.vale.ini` that **fails at the branch point before the change and passes after**. Prose-only changes must instead carry a paired coverage assertion (e.g. "`_data/symptoms.yml` has >= 6 entries and each renders a page present in `_site`").

### Code Quality & Style Rules

- File naming is kebab-case `.md` throughout. Images are kebab-case PNGs named after the page they illustrate, optionally suffixed `-1`, `-2`. Keep both conventions.
- Every page must carry a unique, non-default `description:` in front matter. Today all 28 pages inherit the single `_config.yml` description.
- **Never hardcode a currency figure in a page.** Prices, plan allowances, credit costs, commission rates, match rates, uptime and latency belong in `_data/pricing.yml` and are rendered through Liquid. `script/check.rb` asserts no `£`, `€` or `$` appears outside `_data/pricing.yml`.
- Vocabulary is locked by `_data/glossary.yml` and enforced by Vale. The object model has exactly one name per concept: **Signal, Search, Filter, Persona, Lead list (= `project` in the REST API), Credit**. Aliases such as "personation", "project" used for a lead list in prose, "campaign", "list" are Vale errors.
- Affiliate URLs (`?via=`, `?fp_ref=`) must be emitted through the shared include, which is structurally incapable of producing a link without `rel="sponsored nofollow"` and its cost label.
- Screenshots are a liability: 70 PNGs, 62 with empty alt text, many showing UI that has since changed. Prefer a text click-path plus a field table over a new screenshot.

### Critical Don't-Miss Rules

- **`_config.yml:7` `url: https://docs.signalsapi.com/` has a trailing slash**, so every canonical, `og:url` and JSON-LD URL on all 28 pages renders with a double slash (`https://docs.signalsapi.com//features/...`). Deleting that one character is the single highest impact-to-effort change in the repository.
- **`README.md`, `push.sh`, `run.sh`, `LICENSE`, `Gemfile` and `Gemfile.lock` are currently published**, because `_config.yml` has no `exclude:` key. The unedited just-the-docs template README is live at `docs.signalsapi.com/README.md` telling visitors to click "use this template". Any `exclude:` regression must be caught by an assertion, not by review.
- **`features/filter-leads-with-ai.md:32`** contains `[ai-variables.md](ai-variables.md "mention")` — a GitBook-era relative link that has been dead for 21 months. Assume other GitBook artifacts of the same shape exist.
- **`faq.md:51` sells phone numbers at £49/£149/£199 per month, while `features/find-phone-numbers.md` states phones come from the customer's own LeadMagic key.** The two pages contradict each other in production. Resolve by deleting the contradicted figures, not by inventing a reconciled price.
- **Never invent a figure.** If a number is not sourceable from this repository, ship the render mechanism plus a `TODO(owner):` marker in `_data/` that `script/check.rb` flags. This is the highest-risk failure mode in the whole project.
- **No live network call at build time or page-view time.** No Run buttons, live counters, freshness probes or remote fetches. Static fixtures served from the docs origin are the sanctioned substitute.
- **No string may imply a live sandbox key, a public API base URL, or an issued credential exists.** The agent-data-plane work ships an OpenAPI spec, static fixtures and `prism mock` instructions only. Enforce with a Vale deny rule.
- Bulk page deletion is only permitted when paired with `jekyll-redirect-from` entries **in the same commit**. The URL surface is the site's only SEO asset.
- Legal and compliance copy (privacy policy, DPA, sub-processor lists, GDPR guidance, accessibility conformance claims) is drafted to `_drafts/` only — never published from this workstream.
- Do not touch `app.signalsapi.com` or the application repository. This repository may publish a contract; it may not claim the application consumes one.
- The changelog (`whats-new/index.md`, 3,478 words, 53 PNGs) has been dead since 2025-04-09 and is the only record of several shipped features. Treat it as a data source to migrate, not as dead weight to delete.
